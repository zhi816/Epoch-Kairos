# Academic Paper Translator（繁體中文學術論文翻譯與版面重建）

## 目標與優先順序

忠實翻譯使用者指定的內容，準確保留研究主張、證據與限制，並盡可能沿用原論文的版面設計。不得宣稱百分之百保真或零錯誤；只能描述實際完成並核對的範圍。

遇到取捨時，依序保護：**事實與語意正確、內容完整、可讀性、版面相似度**。在可讀範圍內盡量貼近原稿，不為了追求頁數完全相同而縮到難以閱讀、裁切或省略內容。

## 版面保真

將原 PDF 視為排版範本，不套用大幅改造的通用新模板。盡量保留原稿的紙張方向與尺寸、欄數與閱讀順序、頁邊距、標題與作者區、章節層級和編號、段落分界、字體層級、行距、縮排、頁眉頁腳、頁碼、圖表大小與所在區域，以及圖表標題的位置。

- 沿用原稿的表格風格；不可一律改成三線表。保留欄列結構、合併儲存格、對齊、線條、底色、粗斜體、星號、單位、表註與標題。
- 優先使用原始圖、照片、圖表或架構圖，不任意重繪。若圖內文字需要翻譯，只有在能逐項核對時才修改；無法可靠修改時保留原圖並在交付說明中指出。
- 不任意合併或拆分段落、表格列或章節。中文長度造成溢版時，先局部微調換行、段前段後距、行距或儲存格留白；字級只能小幅調整且須保持易讀。允許頁數或分頁點改變，避免大幅重排、擠壓或裁切。
- 文字翻譯或使用者只要求部分內容時，依其指定範圍工作；不要默默把部分譯本標為全文譯本。

## 翻譯與證據規則

- 保留原文的否定、限定語、因果強度、不確定性、比較對象、適用範圍與作者立場。不得把相關性改成因果性、局部結果概括成普遍結論，或把譯者推論寫成作者發現。
- 公式、變數、數字精度、單位、語言代碼、模型／資料集名稱、程式碼、識別碼、引用標籤與網址照原文核對保留。參考文獻預設維持原文書目資料；全文翻譯不得因排版方便而省略參考文獻、註腳、附錄或補充材料。
- 數據不得憑記憶、摘要或推測補入。逐一核對正文中的結果陳述與表格、圖表、附註；特別核對模型、語言方向、基線、資料集與切分、指標、數值、單位、平均方式、顯著性標記及比較方向。
- 對每張表逐格核對欄名、列名、數值、單位、合併欄、表註與最佳值標記。對每張圖核對圖例、座標、標籤、數值與正文解讀。
- 建立本次任務使用的術語表，全文固定用法。預設用詞：low-resource＝低資源；in-context learning＝上下文學習；machine translation＝機器翻譯；monolingual data＝單語資料；parallel corpus＝平行語料庫；back-translation＝回譯；forward-translation＝正向翻譯；synthetic data＝合成資料；fine-tuning＝微調；pre-training＝預訓練；transfer learning＝遷移學習；language model priors＝語言模型先驗；regularization＝正則化。依領域或使用者指定更新，並記錄實際採用的詞。
- 遇到原文模糊、OCR 不確定、表格結構無法判讀或來源版本不一致時，不猜測、不靜默修補。回看原頁影像與可用的正式來源；仍無法確認時，在核對紀錄中標出位置與問題，並在交付說明中揭露。

## 執行流程

1. **盤點來源與範圍**：確認來源版本、PDF 頁數及使用者要求全文或節選。盤點標題、作者、摘要、各節、表格、圖片、公式、註腳、參考文獻、附錄與補充材料；建立清單以追蹤是否全部處理。雙欄論文須以頁面影像確認閱讀順序，不能只信任文字抽取結果。
2. **翻譯並維持對齊**：依原順序逐段翻譯，保留章節編號、段落邊界、交叉引用和圖表出現次序。整理數字與專有名詞的來源位置，避免不同章節對同一結果使用不一致的數值或說法。
3. **依原稿重建版面**：先沿用原有欄數、層級、留白和圖表樣式，再做維持可讀性所需的最小調整。不要預設輸出頁數必須與原文相同。
4. **兩階段內容核對**：先宏觀、再微觀，依〈兩階段驗證與吸引子檢查〉進行。宏觀用來源清單確認沒有漏節、漏表、漏圖或漏附錄，且論證主線與原文一致；微觀比對正文語意、數據、公式、引用、專名與術語，表格逐格、圖表逐項核對，並做吸引子檢查。抽取文字無法證實的內容須回看原頁。
5. **逐頁檢查成品**：輸出 PDF 後確認檔案可開啟、頁面齊全且文字可讀；渲染並檢查每一頁，對照原頁版面，查看文字或公式是否缺字、重疊、裁切，圖表是否模糊、表格是否錯列或斷裂、標題與圖表是否分離，以及頁眉頁腳和頁碼是否正確。無法執行視覺檢查時，明確說明未核對的部分。
6. **保留可追溯性**：保留簡短核對紀錄，記載重要數據所對應的原文頁碼／表圖、未處理項目與不確定處。保護原始 PDF；中間檔放在專案既有的工具或暫存目錄，遵守該專案的檔案規範。使用可用的 PDF 輸出工具，不寫死瀏覽器安裝路徑；等待產檔程序完成並確認輸出可開啟。預設只產生一份標準譯本，只有使用者或既有整合明確需要時才建立別名檔。

## 兩階段驗證與吸引子檢查

譯完後依下列順序驗證，不可顛倒：逐句核得再準，也救不了漏章或主線走樣的譯本；宏觀修正又常會改動細節，先做微觀等於白做。

**第一階段：宏觀審核。** 先不逐句看，對照原文整體回答下列問題。任一項有問題就先修正，修完重跑本階段，確認沒有問題才進入第二階段。

- **範圍與完整度**：對照來源清單，章節、表、圖、公式、註腳、參考文獻、附錄與補充材料都在；標示的「全文」或「節選」與實際相符。
- **論證主線**：只讀譯本的摘要、各節首段與結論，得到的研究問題、方法、主要結果與限制，與讀原文得到的相同。
- **整體語氣**：譯本整體沒有比原文更肯定或更保留。
- **結構與順序**：章節順序、雙欄閱讀順序、圖表與交叉引用的位置對應原文。
- **版面整體**：欄數、標題層級與表格風格沿用原稿，沒有被通用模板取代。

**第二階段：微觀審核。** 宏觀無誤後，逐段、逐句、逐格核對（見〈翻譯與證據規則〉與〈執行流程〉第 4 步），並逐類檢查吸引子。

吸引子（attractor）指生成譯文時，把輸出拉向模型熟悉的樣式、而偏離原文的力量。受影響的句子通常通順又合理，因此最難發現：

| 類型 | 典型表現 | 檢查方法 |
|---|---|---|
| 流暢化 | 為了中文順口，刪掉 may、suggest、in our setting 等限定語，合併或拆開句子，補上原文沒有的「因此」、「顯示」等因果連接詞 | 逐句對照原文的限定語、否定詞與因果詞 |
| 術語正規化 | 罕見術語、語言名或族語拼寫被換成熟悉的近似詞；術語表的預設詞被套到原文刻意區分的概念上 | 專名與族語詞照原文拼寫；術語表與原文用法衝突時以原文為準並記錄 |
| 知識先驗 | 原文模糊或 OCR 不清處，以「應該是」的常識補齊；作者的分類或定義被改成通行說法 | 回看原頁影像；仍無法確認者標出，不以常識補 |
| 常見值 | 數字精度、小數位、正負號、最佳值標記或語言方向被改成慣用形式 | 表格逐格、數字逐位比對原頁 |
| 版型 | 表格被套成三線表、圖說移到慣用位置、標題層級改成通用模板 | 對照原頁版面 |
| 鄰近內容 | 同批次前一篇譯本的術語、模型名、資料集名或作者名被帶進這一篇 | 與同批次譯本比對專名 |
| 舊版錨定 | 取代既有譯本時沿用舊版的措辭與錯誤，或以舊譯本代替原文核對 | 一律以原文核對，舊譯本只作參考 |

簡便的自問：**這句是原文說的，還是中文讀起來「應該」這樣說？** 後者是高風險候選，須回原文確認。

## 交付說明

簡要列出來源與輸出檔、翻譯範圍（全文或節選）、已核對的內容與方法、未翻譯或無法確認的部分，以及為適應中文而做的版面調整。交代兩階段驗證的結果：宏觀審核發現並修正了什麼、微觀審核查到哪些類型的吸引子及如何處理；沒有發現時寫明檢查範圍。只報告實際完成的檢查；避免使用「百分之百保真」、「完全無誤」或「出版級」等無法由檢查證明的保證。

## 後續工具鏈擴充備忘（PDF 結構解析引擎）

針對雙欄科研排版、高密度實驗數據表與複雜公式之解析，純多模態大模型視覺直接讀取容易產生微觀數據幻覺或耗費大量 Token。後續評估納入跨平台（Windows 與 macOS 雙機環境）之階梯式文檔處理工具鏈：

1. **第一層（輕量文字抽取）**：`pymupdf` (fitz) 或 `pdfplumber`，針對數位排版 PDF 進行無損、極速文字抽取，完全避免數值辨識誤差。
2. **第二層（專業結構與公式解析）**：
   - **IBM Docling**：現代化文檔解析庫（`pip install docling`），支援 DocLayNet 版面分析、表格結構化與 Markdown 導出，跨平台相容性佳。
   - **OpenDataLab MinerU**：專為學術論文與教材設計之高精度解析工具，具備優異之 LaTeX 數學公式與雙欄閱讀順序還原能力。
3. **第三層（多模態大模型綜合與 Watchdog）**：由大模型專注於學術推理、概念萃取與跨頁交叉核對，而非單純承擔 OCR 苦工。
4. **跨平台設計要求**：未來實作封裝為腳本或獨立 Skill（如 `paper-pdf-parser`）時，須具備環境自動探測與套件缺失指引（Graceful Fallback），確保在 Windows 與 Mac 雙機皆可平順運行。
